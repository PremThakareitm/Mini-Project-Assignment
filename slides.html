From Raw Investor Data to Funding Intelligence

Addressing raw data noise and target leakage to deliver reliable predictions.

❌ PROBLEM
  • • Startup funding records contain mixed numerical and unformatted text fields.
  • • Raw variables do not directly represent business investment capacity signals.
  • • Heavy right-skewness in funding check sizes distorts model gradient fitting.
  • • Unbounded range fields risk severe target leakage if included naively.
✅ SOLUTION
  • • Canonicalize city hubs (Bengaluru, Mumbai, Delhi NCR) & clean data anomalies.
  • • Engineer domain signals (investor age, exit success rate, focus density).
  • • Apply log1p target transformation to stabilize continuous check size variance.
  • • Package leak-free transformers into a reproducible scikit-learn Pipeline.
RAW DATA ➔ FEATURE ENGINEERING ➔ ML REGRESSION MODEL ➔ FUNDING CHECK SIZE (INR/USD)

Feature Engineering: The Core of the Project

Converting raw dataset columns into measurable domain investment signals.

Raw Column Engineered Feature Domain Rationale / Value Added
founded_year investor_age_years Measures firm maturity & market cycle experience.
funding_month month_sin + month_cos Captures annual seasonality without artificial 12-to-1 boundary distance.
portfolio_companies + exits exit_success_rate Normalizes exits count relative to portfolio size (exits / portfolio).
ai_focus + fintech_focus + ... focus_sector_count & is_tech_specialist Quantifies domain concentration and multi-sector specialist status.
investment_stage investment_stage_rank Encodes stage hierarchy (Pre-Seed: 1 ➔ Seed: 2 ➔ Series A: 3 ➔ PE: 6).
“Instead of asking the model to learn everything from raw columns, I encode domain knowledge into measurable signals.”

Making Features Reliable

3-part pipeline ensuring reproducibility, out-of-fold protection, and leakage prevention.

1. CLEAN
  • • Median imputation for missing numeric fields.
  • • Canonicalize city hubs (Bengaluru, Mumbai, Delhi NCR).
  • • Standardize binary flags (Yes/No ➔ 1/0).
  • • StandardScaler & OneHotEncoder in ColumnTransformer.
2. PROTECT (LEAKAGE)
  • • 80/20 Train/Test split BEFORE preprocessing.
  • • Exclude min_investment_usd & max_investment_usd bounds.
  • • All scalers fitted ONLY on training split fold.
  • • Encapsulated inside sklearn Pipeline.
3. SELECT & EXPLAIN
  • • Correlation & variance threshold filtering.
  • • Tree-based feature importance weights.
  • • SHAP (SHapley Additive exPlanations) attributions.
  • • Local waterfall explanation per prediction.
Rule: “Preprocessing transformers are fitted on training data only.”
⚠️ DATA LEAKAGE ➔ FALSELY GOOD MODEL
